# OpenSPSS v1.2.0 规划(草案)

> 状态:**规划草案**(分支 `feat/1.2.0`)· 基线:v1.1.3(0115f36)· 日期:2026-10-27
> 版本定位:小版本(minor),以新增能力为主,不做破坏性变更。

## 一、背景:1.1.x 已经有什么

- **108 个分析模型 / 11 大类**,声明式注册,新增模型自动获得前端表单、类型校验、结果渲染与导出。
- **数据层**:7 类格式上传、8 套示例、数据工作台(单元格编辑、撤销重做、增删行列、变量/值标签、合并)、加权个案、落盘持久化与重启恢复。
- **结果层**:智能解读、ECharts 图表、Excel 导出、分析即代码(41 个高频模型)、综合分析报告(HTML / Word / PDF)、历史回放。
- **体验与工程**:暗色主题、pytest 全量冒烟、CI、exe 打包与品牌过渡页。

结论:分析能力与单次分析体验已比较完整,**1.2.0 的主攻方向是"数据与方案的生命周期管理"**——数据能删、能改名、能导出带走;一次研究会话能存成方案、跨重启复用与批量重放。

## 二、需求与差距分析(代码勘察证据)

| # | 需求/缺口 | 证据 | 影响 |
|---|---|---|---|
| 1 | 示例数据集无法删除 | 后端 `DELETE /api/datasets/{ds_id}`(`app.py:175`)对示例数据本就生效;是前端隐藏了删除入口:`app.js:87` 对 `source === "sample"` 不渲染「×」,欢迎页「我的数据集」行(`app.js:164`)则完全没有删除按钮 | 示例数据与上传数据一样落盘(`samples.py:202` 经 `STORE.add` 持久化),重启后仍在,只会越积越多,占满 `MAX_DATASETS = 30` 容量 |
| 1b | 重复点击示例卡会不断生成副本 | 每次点击都走 `POST /api/datasets/sample/{key}` → `samples.create` 生成**新 id** 的新数据集,无同名检测 | 配合「可删除」补一个同名去重,否则用户在堆积与清理之间反复横跳 |
| 2 | 分析记录纯内存,重启即失 | `S.history`(`app.js:759`)存了完整的可复现快照(`modelId / dsId / slots / options`),上限 30 条,但不落盘;报告页定位是「本次会话」 | 做完一次研究无法下次继续;想对新数据重跑同一套分析只能逐个模型手点 |
| 3 | 数据集不能重命名 | 仅有列重命名 `POST /api/datasets/{id}/rename`;数据集名在上传时由文件名定格,合并后形如「a+b」 | 多数据集管理时无法整理命名 |
| 4 | 数据集无法导出带走 | 全部导出端点只面向**结果**(`/api/export/xlsx`、报告 docx/pdf);工作台里改过的数据、模型写回的派生列(主成分得分、聚类类别、预测值,经 `write_col` 落盘)没有任何下载通道 | 数据加工链路「进来 → 加工 → 出不去」,是当前最实际的能力缺口 |
| 5 | SEM / 路径分析缺口 | v1.1.0 规划(`docs/ROADMAP-v1.1.0.md` P2)明确「单独排 1.2.0」 | 承接上版承诺 |

## 三、1.2.0 主题与优先级

一句话目标:**从"会话内好用"到"研究资产可管理"**——数据集可删、可名、可带走;分析可存、可续、可批量重放。

### P0(必做,构成发版主打)

#### A. 示例数据集支持删除(约 0.5~1 天)

后端零改动(删除端点已通用),改动集中在前端与交互细节:

1. **放开三处删除入口**(带确认弹窗,删除不可逆且已落盘):
   - 侧栏数据集切换 popover(`app.js:87`):去掉 `source === "sample"` 判断,示例数据集保留「示例」徽标 + 可删;
   - 欢迎页「我的数据集」行(`app.js:164`):补删除按钮(上传数据同样受益);
   - 数据页顶栏:当前数据集提供「删除」入口(可选,顺手补齐)。
2. **同名示例去重**:点击示例卡时,若已存在同名且 `source="sample"` 的数据集,直接切换过去并 toast 提示,不再生成副本;数据页为示例数据集提供「恢复初始示例」按钮(固定种子,重建覆盖),与删除配合形成"重置"闭环。
3. **删除确认**:当前 `delDataset` 是直接删;统一改为确认弹窗(删除当前使用中的数据集时明确提示),复用现有确认框样式。
4. 细节:删除的是 `S.ds` 当前数据集时,沿用现有清理逻辑(清 localStorage 记忆、刷新列表);容量驱逐(`MAX_DATASETS=30` 静默淘汰最旧)顺带在 `add` 返回被逐名称、前端 toast 一次,让"为什么少了一个数据集"可解释。

#### B. 分析方案落盘管理(约 3~5 天,本次主打)

把"一次研究会话"存成**可持久化、可重放、可整理的分析方案**(类比 SPSS 的语法/输出管理):

1. **数据结构**:方案为 JSON 文档,只存"怎么算",不存结果(重放生成,避免落盘膨胀):
   ```json
   {"v": 1, "id": "…", "name": "员工满意度研究", "created": 0, "updated": 0,
    "steps": [{"model": "linear_regression", "modelName": "多元线性回归",
               "dsId": "…", "dsName": "员工满意度调查(300条)",
               "slots": {"y": "…", "x": ["…"]}, "options": {"…": "…"}, "slotsText": "…"}]}
   ```
   步骤字段直接取自现有历史快照(`app.js:759`),与回放(`replayHistory`)天然兼容。
2. **存储**:`core/storage.py` 增 `plans_dir()`(与 datasets 同级:exe `%APPDATA%/OpenSPSS/plans`;源码 `data/plans`),每方案一个 `<id>.json`,原子写(复用 .tmp + replace 模式),启动时惰性加载。
3. **API**(约 6 个端点):
   - `GET /api/plans` 列表(含步骤概要);
   - `POST /api/plans` 新建 `{name, steps}`(前端从会话历史剥掉 result 后提交);
   - `PUT /api/plans/{id}` 重命名 / 追加当前会话分析 / 替换步骤;
   - `DELETE /api/plans/{id}`;
   - `POST /api/plans/{id}/run` **批量重放**:顺序执行各步,按 dsId 解析数据集(已删 → 该步标记「跳过」并说明,不中断后续),复用现有 `REGISTRY.validate` + runner,返回逐条 `{status, result | error}`;
   - `GET /api/plans/{id}` 详情(P2 可并入列表)。
4. **前端**(入口收敛在「综合分析报告」页,不新增侧栏项):
   - 报告页顶部工具条:「💾 存为分析方案」(命名弹窗,默认取数据集名);「📋 方案」打开方案管理抽屉;
   - 抽屉内:方案列表(名称/步骤数/更新时间)、运行全部、重命名、删除;单方案详情展示步骤清单,每步可单独「重新运行」(复用回放)或移除;
   - 批量运行体验:逐条渲染、失败步骤标红显示错误文案、结束 toast 汇总(n 成功 / m 跳过);运行期间按钮防重复点击;
   - 方案状态独立于 `S.history`,不污染会话报告。
5. **边界**:数据集被删(尤其 A 开放示例删除后更常见)→ 步骤级「数据集缺失,请改绑」状态,首版支持一键改绑到当前数据集;步骤引用的列已被删 → 走现有校验报错文案透出。

### P1(自由探索项,按价值排序;做不完顺延,不阻塞发版)

| 项 | 说明 | 预估 |
|---|---|---|
| C. 数据集导出下载 | `GET /api/datasets/{id}/export?format=csv\|xlsx`;csv 用 utf-8-sig(Excel 中文兼容),列顺序/类型与列元数据一致,文件名取数据集名;数据页顶栏加「⬇ 导出数据」。这是把"加工 + 派生列写回"成果带出应用的唯一通道 | 1 天 |
| D. 数据集重命名 | `PUT /api/datasets/{id}/name` + `Dataset.name` 更新落盘;数据页顶栏名称可点击编辑;方案步骤显示名以运行时数据集为准 | 0.5 天 |
| E. 方法补充(按需取舍,三选一~二) | ① **SEM / 路径分析**:semopy,承接 v1.1.0「单独排 1.2.0」的承诺,注意新依赖对 exe 打包体积的影响(spec 需收集);② **倾向得分匹配(PSM)**:Logistic + scikit-learn 最近邻,输出匹配后平衡性检验;③ **元分析**:输入研究-效应量-标准误表,森林图/漏斗图 | 1~3 天/项 |

### 明确不做(防止范围膨胀)

- **国际化 / 多语言**:本次明确不做。界面保持纯中文;不引入文案抽取层与 i18n 框架;模型 `desc` 等元数据维持中文书写,不预留多语言字段;延续 v1.1.1 建立的全角标点规范(半角 → 全角归一注册时统一处理)。此决定与 v1.1.0 backlog 一致,后续有英文用户信号再议。
- 云同步 / 在线协作:与「纯本地、数据不出本机」定位冲突。
- 数据页虚拟滚动:v1.1.0 已实测分页 + 行数选择器够用。
- 自动更新、多语言报告模板、后台任务队列(批量重放首版用顺序同步执行)。

### P2 / Backlog

- 方案导出 / 导入 JSON 文件(跨机器分享研究方案);
- `sav` 格式导出数据集(pyreadstat `write_sav`,带变量/值标签);
- 方案步骤拖拽排序、复制方案;
- 示例数据集收藏/隐藏(列表内不展示,需要时恢复)——若 A 的去重方案上线后仍有诉求再做。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 方案引用的数据集被删除或被 30 上限驱逐 | 步骤级状态与提示(P0-B 第 5 点);驱逐在 `add` 返回被逐者并由前端 toast,可解释 |
| 批量重放遇到长耗时模型,请求阻塞 | 顺序执行 + 逐条返回进度渲染;单步错误隔离(捕获后标记该步失败继续);后台任务队列明确不做(见"明确不做") |
| semopy 新依赖拖累 exe 体积/打包 | P1-E 末位执行,打包验证放 M3;失败则该项顺延,不阻塞发版 |
| 放开示例删除后,用户误删且示例与自建数据混淆 | 删除一律带确认弹窗;示例数据保留「示例」徽标;「恢复初始示例」提供一键重建兜底 |
| 前端为原生 JS、报告页状态复杂度上升 | 方案状态与渲染独立成块,不与 `S.history` 交叉引用;抽屉/弹窗复用现有 popover/closeModal 体系 |
| 范围膨胀 | P1 之外一律不动;P2 明确记录于此文档,下版再议 |
