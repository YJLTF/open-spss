# OpenSPSS v1.1.0 规划(草案)

> 状态:**已实现**(v1.1.0,分支 `feat/1.1.0`)· 基线:v1.0.1(95ad0b3)· 偏差:代码导出覆盖 41 个模型(超出规划的高频 20 个);P1 的加权个案/暗色主题/Word 导出/历史回放/虚拟滚动未纳入本版,顺延
> 版本定位:小版本(minor),以新增能力为主,不做破坏性变更。

## 一、背景:1.0.x 已经有什么

- **100 个分析模型 / 11 大类**,全部通过 `register_model` 声明式注册;新增模型的前端表单、类型校验、结果渲染、Excel 导出自动生效。
- **数据层**:上传(csv/xlsx/xls/sav/tsv/json/parquet)、7 套示例、三级变量类型(定量/定类/定级)、9 种数据处理操作、落盘持久化与重启恢复。
- **结果层**:智能解读、ECharts 可视化(导出 PNG)、全表导出 Excel、会话级综合报告(导出独立 HTML)。
- **桌面**:单文件 exe、品牌过渡页、端口回退、异常日志。
- **工程**:pytest 109 项(含 100 模型逐一冒烟),版本号单一来源。

结论:分析能力密度已经很高,**短板集中在"数据工作台体验"与"研究全流程可复现"**——这是 1.1.0 的主攻方向。

## 二、差距分析(代码勘察证据)

| 缺口 | 证据 | 影响 |
|---|---|---|
| sav 的变量/值标签在读取时被丢弃 | `open_spss/core/datasets.py:175` 只取 `df`,未用 `meta` | 从 SPSS 迁移来的用户丢失标签,结果可读性差 |
| 列元数据 `labels` 字段预留但从未写入/展示 | `open_spss/core/datasets.py:34` | 前端与结果渲染均无标签概念 |
| 数据页只能看不能改,改数需借道处理工作台 | `open_spss/web/assets/app.js`(预览表为只读渲染) | 改一个错值也要绕路 |
| 数据操作只追加日志,无撤销 | `open_spss/core/datasets.py` 的 `log: list[str]` | 误操作(筛选/缩尾)不可逆,只能重新上传 |
| 无数据集间合并(追加/关联) | API 仅 upload/sample/process/rename/delete(`open_spss/app.py`) | 多文件合并需导出后用外部工具 |
| 方法缺口:偏相关、重复测量 ANOVA、混合模型/GEE、中介、调节、McDonald's ω 均无 | `open_spss/models/` 全量 id 清单核对;`reliability.py` 仅 Cronbach α/折半 | 问卷研究用户刚需(尤其中介/调节,SPSS 生态 PROCESS 插件最高频) |
| 每次分析不留可复现代码 | `open_spss/core/results.py` 的 Result 结构无 code 字段 | 科研用户写方法学描述/复跑困难 |
| 无暗色主题、无 CI | `open_spss/web/assets/styles.css` 单一浅色;仓库无 `.github/workflows` | 体验与工程保障 |

依赖已就绪:statsmodels 0.15 自带 `AnovaRM / MixedLM / GEE / Mediation`,无需新增依赖。

## 三、1.1.0 主题与优先级

一句话目标:**从"能分析"到"好用、可信、可复现"**。

### P0(必做,构成发版主打)

#### A. 方法补全 —— 新增 8 个模型(100 → 108)

按现有 `register_model` 三步法实现,冒烟测试自动覆盖。优先级从高到低:

| 模型 | 大类 | 实现要点 | 预估 |
|---|---|---|---|
| 中介效应分析 | 回归建模 | 简单 + 多重/链式中介;`statsmodels.stats.mediation.Mediation` + Bootstrap 置信区间;输出效应占比、判定表(完全/部分/无) | 1.5 天 |
| 调节效应分析 | 回归建模 | 层次回归:中心化交互项;增量 ΔR² 与交互项显著性;简单斜率检验(±1SD)+ 交互效应图 | 1.5 天 |
| 偏相关分析 | 通用统计 | 控制变量偏相关系数 + t 近似 p 值 + 显著性矩阵热力图(手写,不引 pingouin) | 0.5 天 |
| 重复测量方差分析 | 差异检验 | `statsmodels AnovaRM`;Mauchly 球形度检验与 Greenhouse-Geisser 校正手算,若复杂则首版标注局限 | 1.5 天 |
| McDonald's ω | 问卷研究 | 单因子 CFA 载荷计算 ω,与 Cronbach α 同页对比(复用 `reliability.py` 的因子代码) | 0.5 天 |
| 线性混合模型 | 回归建模 | `MixedLM`:随机截距 / 随机斜率;固定效应表 + 随机效应方差成分 + ICC | 1.5 天 |
| GEE 广义估计方程 | 医学统计 | 聚类/纵向数据:Gaussian/Poisson/Binomial 族 + 可交换/AR1/独立作业相关 | 1 天 |
| 小提琴图 | 统计绘图 | KDE 密度多边形渲染进 ECharts(复用 `core/charts.py` 构建器) | 0.5 天 |

注:README 与过渡页的模型数、11 大类分组表需同步更新(过渡页已是构建时动态注入,README 仍为静态,建议此次一并做"计数单一来源"脚本)。

#### B. 数据工作台 —— 数据页从只读到可编辑

1. **单元格编辑**(2 天):数据页预览表双击编辑,新增 `PUT /api/datasets/{id}/cell`(行、列、值),编辑后该列重跑类型推断并落盘;支持增删行、增删列。
2. **变量标签 / 值标签贯通**(2 天):
   - 读取:上传 sav 时保留 `pyreadstat` 的 variable/value labels;xlsx 支持可选"标签行"。
   - 存储:写入已预留的 `labels` 字段;新增 `PUT /api/datasets/{id}/columns` 扩展支持编辑标签。
   - 展示:变量芯片 tooltip、结果表头、交叉表水平/垂直值均优先显示标签(附原始值)。
3. **撤销 / 重做**(1.5 天):数据操作栈(df 快照,容量 20),Ctrl+Z / Ctrl+Y;与落盘联动。
4. **数据集合并**(1.5 天):`POST /api/datasets/{id}/merge` 支持纵向追加(按列名对齐)与横向关联(key 列,left/inner,冲突列加后缀);入口放在数据页。

#### C. 可复现性 —— 分析即代码(首版覆盖高频 20 个模型)

- Result 结构增加 `code` 字段:每个分析生成等效、可直接运行的 statsmodels/scipy Python 代码片段(含数据准备与调用参数)。
- 结果页新增"查看代码"抽屉:复制按钮 + 说明;综合分析报告导出时附全部分析代码段,构成"数据 + 结论 + 代码"完整档案。
- 首版覆盖:回归族、t 检验族、方差分析族、卡方、相关、描述统计(约占日常使用大头);其余模型逐步补齐,缺失时按钮不展示。

#### D. 工程 —— CI 流水线(0.5 天)

- GitHub Actions:push/PR 触发 `pytest`;tag 触发 wheel 构建。exe 构建暂留本地。

### P1(争取完成,做不完顺延 1.1.1)

| 项 | 说明 | 预估 |
|---|---|---|
| 加权个案 | 指定权重列;首版支持描述统计、频数、交叉表卡方 | 2 天 |
| 暗色主题 | CSS 变量化 + ECharts 主题注册 + 手动切换并记忆 | 2 天 |
| 报告导出 Word / 直接 PDF | docx 后端生成(报告模板化);PDF 走后端渲染,免去"浏览器打印" | 2~3 天 |
| 历史回放 | 结果记录输入快照,支持"重新运行"与参数微调 | 2 天 |
| 数据页虚拟滚动 | >10 万行流畅浏览(现有分页 50 行/页,先测压再决定) | 1 天 |

### P2 / Backlog(明确不进 1.1.0,防止范围膨胀)

- **SEM / 路径分析**:需引入 semopy,依赖与复杂度都重,单独排 1.2.0。
- **元分析**(森林图/漏斗图)、**倾向得分匹配 PSM**:需求真实但非主航道,进 backlog。
- **界面国际化(英文)**:文案量巨大,等有英文用户信号再做。
- **在线协作 / 云同步**:与"纯本地、数据不出本机"定位冲突,不做。

## 四、里程碑(建议顺序)

## 五、测试与验收

- 新模型自动进入 `tests/test_smoke_all_models.py` 的全量冒烟;另为中介/调节/偏相关/混合模型写数值断言单元测试(对照 statsmodels 手工小样本)。
- 数据工作台:为 cell 编辑、撤销、合并、标签读写补 pytest(httpx 已在 dev 依赖)。
- 验收线:全部测试通过;exe 冒烟(启动过渡页、上传 sav 显示标签、跑中介分析、导出报告);README 模型清单与实际注册数一致(新增一致性测试:注册数 == README 表格模型数,防止文档漂移)。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| AnovaRM 球形度校正实现复杂 | 首版输出未校正 F 检验并明确标注;GG 校正作为独立子任务,做不完不阻塞发版 |

| 范围膨胀 | P1 之外一律不动;backlog 项明确记录于此文档 |
